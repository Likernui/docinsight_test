# DocInsight

DocInsight — десктопное приложение для извлечения сущностей из учебных и проектных документов. Проект обрабатывает DOCX, PDF и изображения, извлекает текст, разбивает его на фрагменты, находит сущности и показывает результат в пользовательском интерфейсе.

## Возможности

- загрузка нескольких документов;
- извлечение текста из DOCX, PDF, PNG, JPG, JPEG;
- OCR для изображений через EasyOCR;
- очистка текста и разбиение на чанки;
- семантический поиск по документам через sentence-transformers + FAISS;
- извлечение сущностей через regex + GLiNER;
- запуск GLiNER в отдельном subprocess, чтобы сбой ML-стека не ронял GUI;
- пользовательский GUI с темной темой, группировкой сущностей и фильтром по файлам;
- лабораторный GUI для ручной проверки внутренних этапов пайплайна;
- быстрые автоматические тесты базовых правил извлечения.

## Что извлекается

- ФИО студентов / участников;
- ФИО руководителей / кураторов;
- темы проектов и работ;
- дисциплины;
- технологии;
- источники;
- фрагменты программного кода.

Важные правила:

- источники извлекаются структурно, одним блоком списка литературы;
- GLiNER не используется для источников;
- план-график не должен попадать в источники;
- код извлекается блоками, а не отдельными строками;
- одиночный `return` не считается кодовым фрагментом;
- язык программирования для кода отдельно не классифицируется.

## Запуск

### Главный пользовательский GUI

```bash
.venv/bin/python main_gui.py
```

Если виртуальное окружение активировано, можно запускать короче:

```bash
python main_gui.py
```

`main_gui.py` — основной пользовательский интерфейс. Он скрывает технические детали пайплайна: пользователь выбирает документы, отмечает типы данных для извлечения, нажимает "Обработать документы" и получает сгруппированные результаты. В интерфейсе есть выбор файла: можно смотреть сущности по всем документам или по одному документу.

### Лабораторный GUI

```bash
.venv/bin/python test_gui.py
```

`test_gui.py` — не финальный интерфейс, а стенд для проверки пайплайна. Он показывает внутренние этапы: извлечение текста, чанки, ручное построение индекса, семантический поиск и режимы извлечения сущностей.

### Консольная проверка загрузки документов

```bash
.venv/bin/python test_document_loader.py
```

## Тесты

Быстрые тесты правил:

```bash
.venv/bin/python -m pytest test_core_rules.py
```

`test_core_rules.py` не запускает GUI, GLiNER, OCR и тяжелые модели. Он проверяет базовые правила:

- список литературы извлекается одной сущностью-блоком;
- план-график не считается источником;
- функция извлекается одним блоком кода;
- одиночный `return` игнорируется;
- сущности преобразуются в строки для пользовательского UI.

Ожидаемый результат:

```text
5 passed
```

Дополнительная быстрая проверка синтаксиса:

```bash
.venv/bin/python -m py_compile main_gui.py test_gui.py src/entity_service.py src/entity_extractor.py src/pipeline.py
```

## Архитектура

### Пользовательский пайплайн

`main_gui.py` вызывает высокоуровневый пайплайн из `src/pipeline.py`:

```text
Документы
  ↓
src/text_extractor.py
  ↓
src/preprocessor.py
  ↓
src/indexer.py + src/semantic_search.py
  ↓
src/entity_service.py
  ↓
src/gliner_worker.py + src/entity_extractor.py
  ↓
плоские результаты для GUI
```

Пользовательский GUI не показывает чанки, batch size, индекс и технические режимы GLiNER.

### Лабораторный пайплайн

`test_gui.py` оставлен для ручной отладки. В нем можно отдельно:

- извлечь текст;
- предобработать документы;
- посмотреть чанки;
- вручную построить индекс;
- выполнить semantic search;
- извлечь сущности в разных режимах.
