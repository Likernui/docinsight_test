# Техническое задание: DocInsight

## 1. Общее описание

**DocInsight** — десктопное приложение для автоматической обработки, анализа и семантического поиска по корпусу учебных и проектных документов (отчёты, пояснительные записки, PDF, сканы).

**Цель:** Пользователь загружает пачку документов → приложение извлекает текст → очищает → разбивает на фрагменты → находит сущности (имена, технологии, руководители) → позволяет искать по смыслу, а не по ключевым словам → формирует итоговый отчёт.

---

## 2. Поддерживаемые форматы

| Формат | Извлечение | Особенности |
|--------|------------|-------------|
| **DOCX** | python-docx | Параграфы, таблицы, колонтитулы, сноски, стили (заголовки) |
| **PDF** | PyMuPDF (fitz) | Постраничное извлечение текста |
| **PNG, JPG, JPEG** | EasyOCR (OCR) | Сканы/фото документов, мультиязычность (ru+en) |

---

## 3. Архитектура (модули)

```
Загрузка документов (text_extractor.py)
         ↓
Предобработка (preprocessor.py)
         ↓
Векторный индекс (indexer.py)
         ↓
Семантический поиск (semantic_search.py)
         ↓
Извлечение сущностей (entity_extractor.py) ← GLiNER
         ↓
Агрегация (aggregator.py)
         ↓
Генерация отчёта (result_generator.py)
```

## 4. Подробное описание модулей

### 4.1. `src/text_extractor.py` ✅ ГОТОВО

**Задача:** Загрузить сырой текст из файлов любых поддерживаемых форматов.

**Компоненты:**
- `TextExtractor` (абстрактный базовый класс)
- `DocxExtractor` — извлечение текста из DOCX:
  - Параграфы основного содержимого
  - Таблицы (ячейки)
  - Колонтитулы (header/footer)
  - Сноски (footnotes)
- `PdfExtractor` — постраничное извлечение через PyMuPDF
- `ImageExtractor` — OCR через EasyOCR с ленивой загрузкой модели
- `DocumentLoader` — универсальный загрузчик:
  - Автоопределение формата по расширению
  - Одиночная и пакетная загрузка
  - Callback для прогресса

**Вход:** Путь к файлу или список путей
**Выход:** Строка текста или словарь `{путь: текст}`

---

### 4.2. `src/preprocessor.py` ✅ ГОТОВО

**Задача:** Очистить текст и разбить на чанки, готовые для векторизации.

**Компоненты:**
- `TextCleaner` — очистка:
  - Склеивание перенесённых слов (`обработ-\nка` → `обработка`)
  - Схлопывание множественных переносов строк
  - Схлопывание множественных пробелов
- `DocxSectionParser` — структурный анализ DOCX:
  - Определение заголовков по стилям (Heading 1/2/3, «Заголовок N»)
  - Эвристики: жирный текст без точки, центрированные строки
  - Разбиение на секции по заголовкам
- `StructuralChunker` — разбиение на чанки:
  - DOCX: чанки внутри секций (не пересекают границы тем)
  - PDF/изображения: чанки по предложениям
  - Overlap = целые предложения (2 последних предложения повторяются)
- `split_sentences()` — разделение по `.`, `!`, `?`
- `TextPreprocessor` — пайплайн: `очистка → chunking`

**Вход:** Сырой текст + путь к файлу
**Выход:** Список `TextChunk` (текст, путь, индекс, метаданные секции)

---

### 4.3. `src/indexer.py` ⏳ НЕ НАЧАТ

**Задача:** Преобразовать текстовые чанки в векторные эмбеддинги и построить индекс для быстрого поиска.

**Компоненты:**
- `Vectorizer` — обёртка над `sentence-transformers`:
  - Модель: `paraphrase-multilingual-MiniLM-L12-v2` (поддержка ru+en, лёгкая)
  - Batch-кодирование чанков
- `VectorIndex` — хранение и поиск:
  - FAISS index (Flat или IVF)
  - Связь: вектор → TextChunk (file_path, chunk_index, metadata)
  - Сохранение/загрузка индекса на диск
- `IndexBuilder` — пайплайн:
  - Приём чанков из preprocessor
  - Векторизация
  - Построение FAISS индекса

**Вход:** `dict[str, list[TextChunk]]`
**Выход:** FAISS индекс + маппинг `{idx → TextChunk}`

---

### 4.4. `src/semantic_search.py` ⏳ НЕ НАЧАТ

**Задача:** Поиск релевантных чанков по пользовательскому запросу.

**Компоненты:**
- `SemanticSearch` — основной класс:
  - Векторизация запроса (та же модель что и indexer)
  - FAISS поиск top-K ближайших чанков
  - Ранжирование по косинусному сходству
- `SearchResult` — результат поиска:
  - Текст чанка
  - Путь к файлу
  - Индекс чанка
  - Score (косинусное сходство)
  - Контекст (соседние чанки)

**Вход:** Текстовый запрос (естественный язык)
**Выход:** Список `SearchResult` отсортированный по релевантности

---

### 4.5. `src/entity_extractor.py` ⏳ НЕ НАЧАТ

**Задача:** Извлечь из текста структурированные сущности (имена, технологии, должности, организации).

**Технология:** GLiNER (`urchade/gliner_multilingual-v2.1`)

**Почему GLiNER:**
- Zero-shot — работает без дообучения на нашем домене
- Гибкие типы сущностей — задаём сами, не фиксированный набор
- Поддержка русского языка
- Легче и быстрее чем `transformers` + кастомная NER модель
- Можно добавлять новые типы без переобучения

**Компоненты:**
- **`GLiNERExtractor`** — основной NER модуль:
  - Модель: `urchade/gliner_multilingual-v2.1`
  - Кастомные типы сущностей:
    - `человек` — ФИО студентов, преподавателей, авторов
    - `должность` — научный руководитель, консультант, рецензент
    - `технология` — Python, FastAPI, PyTorch, Docker
    - `организация` — университет, кафедра, компания
    - `проект` — название проекта, тема работы
    - `дата` — сроки, дедлайны, годы
  - Zero-shot предсказание — просто передаём список типов
- **`RegexExtractor`** — дополнение регулярками:
  - Номера документов, договоров, ГОСТов
  - Email, URL, версии ПО
- **`EntityAggregator`** — объединение GLiNER + regex, дедупликация

**Пример использования GLiNER:**
```python
from gliner import GLiNER

model = GLiNER.from_pretrained("urchade/gliner_multilingual-v2.1")

text = "Научный руководитель: Иванов И.И. Проект разработан на Python с FastAPI..."

entities = model.predict_entities(text, [
    "человек", "должность", "технология", "организация", "проект", "дата"
])

# Результат:
# [
#   {'text': 'Иванов И.И.', 'label': 'человек', 'score': 0.95},
#   {'text': 'научный руководитель', 'label': 'должность', 'score': 0.88},
#   {'text': 'Python', 'label': 'технология', 'score': 0.92},
#   {'text': 'FastAPI', 'label': 'технология', 'score': 0.90}
# ]
```

**Вход:** Текст чанка или целый документ
**Выход:** Список сущностей `{type: str, text: str, confidence: float, source: str}`

### 4.6. `src/aggregator.py` ⏳ НЕ НАЧАТ

**Задача:** Агрегировать результаты поиска и извлечения сущностей в структурированный вид.

**Компоненты:**
- `ResultAggregator`:
  - Группировка чанков по файлу
  - Сводка сущностей по всему корпусу
  - Статистика: покрытие, уникальные сущности, частотность
- `CorpusSummary`:
  - Топ технологий
  - Топ авторов
  - Список всех проектов
  - Взаимосвязи между документами

**Вход:** Результаты поиска + сущности
**Выход:** Структурированная сводка

## 8. Ключевые требования к обработке текста

1. **Чанки** — только целые предложения, без обрывков слов
2. **Overlap** — 2 последних предложения (настраиваемо 0-5)
3. **DOCX** — структурное разбиение по заголовкам, чанки не пересекают секции
4. **PDF** — разбиение по предложениям, целые фразы
5. **Средний размер чанка:** 400-600 символов
6. **Без потери контекста** — overlap гарантирует что соседние чанки содержат общий фрагмент
7. **Извлечение сущностей** — GLiNER zero-shot, 6 типов: человек, должность, технология, организация, проект, дата
8. **Семантический поиск** — по смыслу, не по ключевым словам
9. **Итоговый отчёт** — DOCX с таблицами сущностей и результатами поиска

## 9. Пайплайн обработки (полный)

```
1. Пользователь выбирает файлы (.docx, .pdf, .png, .jpg)
   ↓
2. text_extractor.py — извлечение сырого текста
   ↓
3. preprocessor.py — очистка + разбиение на чанки
   - DOCX: по заголовкам + предложения внутри секций
   - PDF: по предложениям
   - Overlap: 2 последних предложения
   ↓
4. indexer.py — векторизация чанков (sentence-transformers → FAISS)
   ↓
5. Пользователь вводит запрос
   ↓
6. semantic_search.py — поиск top-K релевантных чанков
   ↓
7. entity_extractor.py — GLiNER извлекает сущности из чанков
   ↓
8. aggregator.py — объединение результатов
   ↓
9. result_generator.py — генерация DOCX-отчёта
```
